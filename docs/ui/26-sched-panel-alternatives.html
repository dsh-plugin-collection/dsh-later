S4 · 复用宿主 Picker当前不可行

自定义时间不再用原生 <input type="date">，改用宿主那套月历 + 三列滚轮。

↑ 483px 浮层，比 S1 高 160px
🕐
↑
证据：宿主确实有，但没公开导出。 @deepseek-ai/dsh-client-ui-schedule@0.2.1-rc.2 里有 PickerPopover / DatePicker（月历）/ ClockPicker（时·分·秒三列滚轮）的类型与实现， 但 lib/client.js 的导出面只有 cordis 的 apply / inject——三个组件都是包内私有； package.json 声明的 "./src/*" 路径在安装包里也没有 src 目录。 所以这条路要宿主先开口子，不是插件单方面能做的。

我的建议：S2 为骨架 + S3 的输入框替掉「自定义…」。 即：点时钟按钮 → composer 上方长出一条定时条，条上是一个能直接打「25 分钟后 / 每 30 分钟 / 明天9点」的输入框， 下面一排补全建议芯片（自带解析出的时刻、按 epoch 去重），右侧一个「定时提醒」按钮。 零遮挡、一次点击、能力最全，且不依赖宿主改任何东西。S4 另开 issue 请宿主导出 Picker，等它落地再把「精确到日历」那条路补上。
顺带纠正我上一版的一处事实错误：我上次建议「标题与按钮统一叫『定时发送』」——反了。 GUI 面板走 /user-schedule-create，delivery 恒为 context（notice 注入），到点是提醒，不会以你的身份发言； 「代发」只有人类手输 /later 才拿得到（trustedDelivery 那道闸门）。 所以标题「定时提醒」是对的，该改的是输入框按钮 tooltip「定时发送」和 CTA 里那个「发送」。

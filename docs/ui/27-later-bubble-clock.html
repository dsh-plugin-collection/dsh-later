能不能做 插槽事实

结论：现在没有现成插槽能画在气泡前。可行的是替换 user 节点的渲染器，再复用官方气泡工厂， 插件内闭环，不用改内核。前提是宿主侧先给 /later 消息加一个来源标记。

必配的一步：现在还分不出哪条用户消息是 /later 发的。 投递时 source 只有 {kind:'user'}，和手动发送的形状完全一样；日志里没有别的痕迹。 要么给 source 加一个来源字段（客户端 node.data.source 会原样带过去）， 要么把投递的 seq 记进投影。这一步不做，三个位置都无从判断该给谁画钟。
路线做法代价判断
影子渲染 user 节点 注册 conversation.chat.node 的 user 键，内部用 renderFactorySlot('conversation.chat.user.content', …) 复用官方气泡、图片与引用摘要， 外面套自己的行容器、时钟和 28px 操作行。 占用唯一的 user 键，和别的影子插件互斥；行容器与操作行要随上游升级维护； 所有用户气泡都走这段代码，需要一轮完整回归。 可做
等上游给插槽 在 user 行里加一个插槽（例如 conversation.chat.user.meta，single， owner props 带 source / time），插件只注册角标。 要等内核发版；在此之前功能不存在。 长期正解
DOM 装饰 MutationObserver 找消息行，往里插节点。 依赖哈希类名和 DOM 形状，React 重渲染会抹掉，跨版本必坏。 不采用

上游插槽建议（若有）

// 期望形状：owner 在气泡前派发，插件只交一个角标组件
ctx.slots.register(
  { name: 'conversation.chat.user.meta', order: 0 },
  ({ source, time }) => source.kind === 'user' && source.producer === 'dsh-later'
    ? <LaterClock time={time} />
    : null,
)

已核对的插槽 0.2.1-rc.2

与用户消息有关的可注册位置只有三处，且都不在气泡前： conversation.chat.user.images（single，替换整个图片画廊）、 conversation.user.text.node（keyed，替换气泡内某一类文本节点，图标只能落在文字行里）、 conversation.chat.node 的 user 键（keyed，替换整行，条目带 renderFactorySlot 席位）。 conversation.chat.user.content 与 conversation.user.text 是 factory， 插件不能往 factory 本身注册条目。所以「气泡前」这个位置只剩替换整行一条路。

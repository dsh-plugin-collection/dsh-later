独立成一轮，等价于正常发送；不会与回合启动竞争。
投递确认
投递后核对会话日志，确认消息真正进入请求。关闭则不再核对，也不保证送达。
未确认时
留档等待重试，并明确提示。
选择「丢弃」后，未确认的提醒会按旧语义移出列表 —— 静默丢失将重新变得可能。
核心能力
核心若提供 steer 回执，此处的可靠性选项将不再必要。

3 · Settings Schema

/** 插话投递：入哪个队列。 */
steerDelivery: s.union([
  s.const('followup'),   // next-turn：独立成轮，竞态在结构上不存在（默认）
  s.const('steer'),      // next-step：更快，但撞 turn/start 会被 claim 吞掉
]).default('followup'),

/** 投递后核对日志中是否出现该 message id。 */
confirmDelivery: s.boolean().default(true),

/** 未确认时：保留可重试 / 丢弃。 */
onUnconfirmed: s.union([
  s.const('keep'),
  s.const('discard'),
]).default('keep'),

4 · 实现要点

项做法
投递按 steerDelivery 分派到 agent.followup / agent.steer
确认append 后读会话日志核对 message id；不监听 inbox/claimed、request/header（避免与核心时序隐性耦合）
幂等未确认且 onUnconfirmed='keep' 时不写 dispatch，条目留在 active 可重试
暂停项steerPausedById 同步受这三项控制
范围全部在插件内；不碰 DSH 核心
